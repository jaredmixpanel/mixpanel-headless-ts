# scripts/

Repository maintenance scripts. Every CLI here carries a shebang and an exec
bit and is reachable through an npm alias (run with `npm run <alias> -- <args>`
to pass flags). Library modules live in `lib/`, `codemods/lib/` and
`audit/*-lib.mjs`; data files sit next to the script that reads them.
Type-checked (as `allowJs`) by `scripts/tsconfig.json`; linted by the
`repo/javascript` block in `eslint.config.js`, which also enforces the shebang
rule (`n/hashbang`).

## Generators

Outputs are committed; never hand-edit them (see
[`CONTRIBUTING.md`](../CONTRIBUTING.md#generated-files--never-hand-edit) for
the freshness tests). `npm run generate:all` runs the three Node generators in
dependency order. The four Python generators run through
`uv run --python <pin>` — the pin is `compat-python.pin.json` and
`gen_provenance.py` makes every generator refuse any other interpreter.

| Script                           | npm alias                     | Writes                                                       | Inputs / flags                                                                                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate-error-codes.mjs`       | `generate:error-codes`        | `packages/core/src/errors-codes.gen.ts`                      | `conformance-runner/corpus/contract/error-codes.json`. `-- --check` exits 1 if the committed file differs from a fresh render.                                                                                                                                                              |
| `generate-api-map.mjs`           | `generate:api-map`            | `conformance-runner/src/api-map.gen.ts`                      | `conformance-runner/corpus/{api-index,typescript-port-api-map}.json`, `conformance-runner/src/{naming-exceptions,authored-apis}.json`. Fails hard on any Python name no naming rule reaches.                                                                                                |
| `generate-bridge-allowlist.mjs`  | `generate:bridge-allowlist`   | `conformance-runner/bridge-allowlist.gen.json`               | Corpus wire vectors, `api-index.json`, `api-map.gen.ts`, `bridge-allowlist-rules.json`, `consent-verbs.json`, `route-verbs.json`; `git rev-parse HEAD`. `--stdout`, `--generated-at=`, `--headless-commit=`, `--rules=`, `--verbs=`, `--route-verbs=` exist for the freshness test.         |
| `generate-non-printable.py`      | `generate:compat-tables`      | `packages/core/src/compat/non-printable.gen.ts`              | The pinned CPython's `unicodedata` / `str.isprintable()`.                                                                                                                                                                                                                                   |
| `generate-decimal-digits.py`     | `generate:compat-tables`      | `packages/core/src/compat/decimal-digits.gen.ts`             | The pinned CPython's `int(ch)` per codepoint.                                                                                                                                                                                                                                               |
| `generate-whitespace.py`         | `generate:compat-tables`      | `packages/core/src/compat/whitespace.gen.ts`                 | The pinned CPython's `str.isspace()` / numeric-whitespace acceptance.                                                                                                                                                                                                                       |
| `generate-canonical-fixtures.py` | `generate:canonical-fixtures` | `packages/core/test/compat/fixtures/canonical-fixtures.json` | A deterministic sample of `builder` vectors from `conformance-runner/corpus/**/*.jsonl` rendered by CPython `json.dumps`; the alias runs Prettier over the output afterwards (required).                                                                                                    |
| `gen_provenance.py`              | —                             | (library)                                                    | Imported by the four Python generators: `require_pinned_interpreter()` exits unless the running CPython / Unicode pair equals the pin; `generator_sha256()` is what each header records, so `tests/generated-tables-provenance.test.ts` can tell an edited generator from a stale output.   |
| `compat-python.pin.json`         | —                             | (data)                                                       | `{ "cpython": "3.14.6", "unicode": "16.0.0" }` — the one place the port's target CPython is spelled; the `generate:compat-tables` / `generate:canonical-fixtures` aliases pass it to `uv run --python`, and the provenance test checks both the aliases and the emitted headers against it. |

Data files read by `generate-bridge-allowlist.mjs` (tables, not code):
`bridge-allowlist-rules.json` (host / family / exclusion / classifier /
write-class rules), `consent-verbs.json` (TS method → consent phrase),
`route-verbs.json` (per-route phrase overrides). They transcribe an external
spec: `docs/specs/heads/01-lease-and-bridge.md` in the `mixpanel-desktop-app`
repository.

## Audits and codemods

Codemods are one-shot tools kept because the transform they encode is the
documentation of a repo-wide convention (and reruns on new code are cheap).
All are idempotent and take `--check` to report without writing; run Prettier
(and `eslint --fix` where noted) over the touched files afterwards.

| Script                                     | npm alias / invocation                                                  | What it does                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `audit/comment-archaeology.mjs`            | `audit:comments` (in `check` as `-- --summary`), `audit:comments:fix`   | Finds comments and test titles carrying port-process identifiers (batch/task ids, `foo.py:123` references, shard/packet vocabulary) and can apply the mechanical rewrites. `--report` (default), `--summary`, `--json <path>`, `--root <dir>`, `--fix [--dry-run]`, positional paths. Exit 1 on hits, 2 on usage/I-O errors. See [`audit/README.md`](audit/README.md). |
| `audit/comment-archaeology-lib.mjs`        | —                                                                       | The pure functions behind the audit (parses with the TypeScript compiler API). `.d.mts` twin for the tests.                                                                                                                                                                                                                                                            |
| `codemods/rewrite-workspace-imports.mjs`   | `node scripts/codemods/rewrite-workspace-imports.mjs [--check]`         | Rewrites cross-workspace relative imports to the bare `@mixpanel-headless/*` specifiers, deciding public vs `/internal` per symbol. `--check` exits 1 if anything would change or is unresolved.                                                                                                                                                                       |
| `codemods/rename-symbols.mjs`              | `node scripts/codemods/rename-symbols.mjs <plan.json> [--check]`        | Renames declared identifiers repo-wide through the TypeScript language service (`findRenameLocations`), so imports, tests, the rig and shorthand properties move together. Used to apply the naming convention (README "Naming").                                                                                                                                      |
| `codemods/entity-generic-base.mjs`         | `node scripts/codemods/entity-generic-base.mjs [--check] [file ...]`    | Moves every `EntityModel` subclass onto the generic base (`extends EntityModel<XInit>`, `fieldSpecs: EntityFieldSpecs<XInit>`, cast-free `super` / `fromDict`, `@internal` off the metadata statics). TS-AST guided; runs Prettier on touched files.                                                                                                                   |
| `codemods/hoist-factory-closures.mjs`      | `node scripts/codemods/hoist-factory-closures.mjs [--check] [file ...]` | Turns a closure factory (`createXMethods(core) { const helper = …; return { m: async () => … } }`) into named module-level functions plus a thin assembly that re-attaches them with `bindFirst`; each hoisted function receives exactly the factory parameters it references.                                                                                         |
| `codemods/hoist-test-helpers.mjs`          | `node scripts/codemods/hoist-test-helpers.mjs [--check] [file ...]`     | Replaces byte-equivalent per-file copies of the core test helpers with imports from `packages/core/test-support/` (table-driven; variant bodies are reported as `KEPT`); prunes the imports the removal orphaned. Run `eslint --fix` + Prettier afterwards.                                                                                                            |
| `codemods/split-test-file.mjs`             | `node scripts/codemods/split-test-file.mjs <plan.json> [--check]`       | Splits test files along their top-level `describe` blocks per a JSON plan, placing the fixture preamble by use: inlined, duplicated when tiny, or hoisted to an exported sibling `*-fixtures.ts`. `split-plan-core-tests.json` is the plan the core suite was split with.                                                                                              |
| `codemods/english-test-titles.mjs`         | `node scripts/codemods/english-test-titles.mjs [--check] [path ...]`    | Rewrites `it("test_snake_case")` / `describe("TestFoo (<name>.py:<n>)")` titles to English words and appends `// python: <name>` to the line; drops bare line citations from titles. Lexical only — review the output. Default scope `packages/core/test`.                                                                                                             |
| `codemods/rename-test-titles-platform.mjs` | `node scripts/codemods/rename-test-titles-platform.mjs <mapping.json>`  | Renames `describe` / `it` titles from a JSON mapping (`{ file: { old: new } }`) and keeps the Python identifier as a `// python: …` first body line. Used for the node/browser/rig test-title pass.                                                                                                                                                                    |

| `typedoc-python-see-links.mjs` | `typedoc.json` (`plugin`)                                                                 | TypeDoc plugin: turns `@see mixpanel_headless.…` provenance tags into links to the Python reference (mkdocstrings anchors are the directive identifier plus member path). module's exports.

## Documentation site (npm aliases only)

No script under `scripts/`; the aliases chain the tools directly. The
layout, page conventions and the twoslash rules are in
[`CONTRIBUTING.md`](../CONTRIBUTING.md#documentation).

| npm alias        | Runs                                                                                            | Notes                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `docs:api`       | `typedoc`                                                                                       | Reference into git-ignored `docs/reference/` (plus the sidebar JSON) from `typedoc.json`; needs `dist/` (`tsc -b`). Emits with warnings. |
| `docs:api:check` | `typedoc --emit none --treatWarningsAsErrors`                                                   | Validation only; exit 3 on any warning. Not in `check` until the count is zero.                                                          |
| `docs:dev`       | `npm run build && npm run docs:api && node --max-old-space-size=8192 …/vitepress.js dev docs`   | Local preview with hot reload.                                                                                                           |
| `docs:build`     | `npm run build && npm run docs:api && node --max-old-space-size=8192 …/vitepress.js build docs` | The site into `docs/.vitepress/dist/`; every `ts twoslash` block is type-checked, dead links fail. Run by `.github/workflows/docs.yml`.  |
| `docs:preview`   | `node --max-old-space-size=8192 …/vitepress.js preview docs`                                    | Serves the last build.                                                                                                                   |

Environment: `DOCS_BASE` (site base path, default `/`; CI sets `/<repo>/`) and
`DOCS_ORIGIN` (origin for absolute URLs in `llms.txt`; relative when unset).
