# scripts/

Repository maintenance scripts. Every CLI here carries a shebang and an exec
bit and is reachable through an npm alias (run with `npm run <alias> -- <args>`
to pass flags). Library modules live in `lib/` and `audit/*-lib.mjs`; data
files sit next to the generator that reads them. Type-checked (as `allowJs`)
by `scripts/tsconfig.json`; linted by the `repo/javascript` block in
`eslint.config.js`, which also enforces the shebang rule (`n/hashbang`).

## Generators

Outputs are committed; never hand-edit them (see
[`CONTRIBUTING.md`](../CONTRIBUTING.md#generated-files--never-hand-edit) for
the freshness tests). `npm run generate:all` runs the three Node generators in
dependency order.

| Script                           | npm alias                                                                              | Writes                                                       | Inputs / flags                                                                                                                                                                                                                                                                      |
| -------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate-error-codes.mjs`       | `generate:error-codes`                                                                 | `packages/core/src/errors-codes.gen.ts`                      | `conformance-runner/corpus/contract/error-codes.json`. `-- --check` exits 1 if the committed file differs from a fresh render.                                                                                                                                                      |
| `generate-api-map.mjs`           | `generate:api-map`                                                                     | `conformance-runner/src/api-map.gen.ts`                      | `conformance-runner/corpus/{api-index,typescript-port-api-map}.json`, `conformance-runner/src/{naming-exceptions,authored-apis}.json`. Fails hard on any Python name no naming rule reaches.                                                                                        |
| `generate-bridge-allowlist.mjs`  | `generate:bridge-allowlist`                                                            | `conformance-runner/bridge-allowlist.gen.json`               | Corpus wire vectors, `api-index.json`, `api-map.gen.ts`, `bridge-allowlist-rules.json`, `consent-verbs.json`, `route-verbs.json`; `git rev-parse HEAD`. `--stdout`, `--generated-at=`, `--headless-commit=`, `--rules=`, `--verbs=`, `--route-verbs=` exist for the freshness test. |
| `generate-non-printable.py`      | `generate:compat-tables`                                                               | `packages/core/src/compat/non-printable.gen.ts`              | The host CPython's `unicodedata` / `str.isprintable()`. | `generate-decimal-digits.py`     | `generate:compat-tables`                                                               | `packages/core/src/compat/decimal-digits.gen.ts`             | The host CPython's `int(ch)` per codepoint. Same pin rule.                                                                                                                                                                                                                          |
| `generate-whitespace.py`         | `generate:compat-tables`                                                               | `packages/core/src/compat/whitespace.gen.ts`                 | The host CPython's `str.isspace()` / numeric-whitespace acceptance. Same pin rule.                                                                                                                                                                                                  |
| `generate-canonical-fixtures.py` | — (`uv run --no-project python scripts/generate-canonical-fixtures.py && npm run fmt`) | `packages/core/test/compat/fixtures/canonical-fixtures.json` | A deterministic sample of `builder` vectors from `conformance-runner/corpus/**/*.jsonl` rendered by CPython `json.dumps`; the `npm run fmt` step is required.                                                                                                                       |

Data files read by `generate-bridge-allowlist.mjs` (tables, not code):
`bridge-allowlist-rules.json` (host / family / exclusion / classifier /
write-class rules), `consent-verbs.json` (TS method → consent phrase),
`route-verbs.json` (per-route phrase overrides). They transcribe an external
spec: `docs/specs/heads/01-lease-and-bridge.md` in the `mixpanel-desktop-app`
repository.

## Launchers and gates

| Script                     | npm alias                    | What it does                                                                                                                                                                                                                               | Inputs / env                                                                                                                                    |
| -------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `run-conformance.mjs`      | `conformance`                | Bundles `conformance-runner/src/cli.ts` from source and replays the corpus; JSON report on stdout, summary on stderr.                                                                                                                      | `-- --report json`, `-- --filter <substring>` (vector-id substring).                                                                            |
| `run-oracle.mjs`           | `oracle`                     | Bundles `differential/oracle/main.ts` from source and runs the oracle-ts stdin/stdout session loop.                                                                                                                                        | Spawned by the Python fuzz harness as `--right "node …/scripts/run-oracle.mjs"`; EOF on stdin exits 0.                                          |
| `browser-smoke.mjs`        | `smoke:browser` (in `check`) | Bundles `packages/core` and `packages/browser` for `platform: "browser"`; fails on any Node built-in or `undici` in the graph, then builds the real IIFE bundle in memory and asserts the required globals.                                | —                                                                                                                                               |
| `build-browser-bundle.mjs` | `build:browser`              | Reproducible browser bundle (IIFE + ESM + provenance manifest) into `dist/browser/`. Refuses a dirty tree unless told otherwise.                                                                                                           | `-- --out <dir>`, `-- --allow-dirty`; `git rev-parse HEAD`.                                                                                     |
| `sync-corpus.sh`           | `sync:corpus`                | Snapshots the Python repo's `conformance/vectors/**`, `conformance/contract/*.json` and `conformance/schema/canonical-selftest.json` into `conformance-runner/corpus/`; aborts unless the source manifest pin equals `corpus.config.json`. | `MP_PYTHON_REPO` (required, path to the Python checkout), `MP_RIG_BRANCH` (worktree branch used when the Python tree is dirty; default `main`). |
| `check-vendor-drift.sh`    | `vendor:drift`               | Verifies every file in `vendor/mixpanel-contracts/PROVENANCE.json` against its sha256; byte-diffs against the analytics checkout when mounted.                                                                                             | `ANALYTICS_ROOT` (optional; read-only; set-but-missing is an error).                                                                            |

## Libraries (`lib/`)

| Module                  | Used by                                                                                   | Purpose                                                                                                                                               |
| ----------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `workspace-aliases.mjs` | `vitest.config.ts`, `browser-smoke.mjs`, `build-browser-bundle.mjs`, `bundle-and-run.mjs` | The one table mapping `@mixpanel-headless/*` specifiers to `src/` (`esbuildAliases()`, `vitestAliases()`), so nothing under test resolves to `dist/`. |
| `bundle-and-run.mjs`    | `run-conformance.mjs`, `run-oracle.mjs`                                                   | `bundleAndImport({ entry, outFile })` — esbuild one TypeScript entry for Node with the aliases, then import it.                                       |
| `lint-ignores.mjs`      | `eslint.config.js`, `tests/ignore-lists.test.ts`                                          | The one list of generated / vendored / local-only paths neither ESLint nor Prettier touches; `.prettierignore` is kept in sync by the test.           |
| `compare-strings.mjs`   | `generate-bridge-allowlist.mjs`, the audit                                                | UTF-16 code-unit comparator for stable, locale-independent sorting in generator output.                                                               |

`*.d.mts` files next to a module are hand-written declarations for the
TypeScript importers (`vitest.config.ts`, tests); keep them in step with the
module's exports.
